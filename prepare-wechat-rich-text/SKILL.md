# 公众号富文本编辑

只把本 Skill 用作已有 `article.md` 的本机排版工具。写作、审稿和定稿由文章所属流程处理；本机保存和复制富文本都不等于用户定稿或公众号验收。

## 前置检查

1. 读取 [编辑器安全与验收](references/editor-safety-and-acceptance.md)。
2. 要求用户提供或明确选择一个已经存在、文件名严格为 `article.md` 的文件。
3. 确认这是本机可视化编辑请求，而不是写新文章、重写内容、推草稿箱或发布请求。
4. 不在未定稿文章上擅自启动；文章所属流程存在人工定稿门禁时，先确认门禁已经通过。

## 启动

用户自行双击：

```text
scripts\rich-editor\launch.cmd
```

Agent 已知文章绝对路径时：

```powershell
scripts\rich-editor\launch.cmd "D:\path\to\article.md"
```

启动器只接受严格命名为 `article.md` 的现有文件。服务只监听 `127.0.0.1`，并从 `assets/rich-editor/` 加载静态资源。

## 编辑边界

- 标题大小只按编辑器实际提供的 H1–H6 标题层级调整；不要承诺任意字号或自定义字体大小。
- 只允许操作所选 `article.md`、同目录 `images/` 及其受控恢复目录。
- 页面中的“上传图片”表示复制到文章旁的本地 `images/`，不是上传外网。
- 保存前检查文件哈希和冲突状态；出现外部修改、未完成事务或恢复提示时，必须让用户选择，不得自动覆盖。
- 只有页面显示已保存、无冲突、无缺图、无上传中项目且无恢复待确认时，才允许复制公众号富文本。
- 不把复制成功说成公众号草稿已保存、已发布或上线检查通过。
- 不删除恢复文件、用户原图或文章原件；清理需要按项目规则另行确认。

## 验收与交付

向用户报告：

- 打开的 `article.md` 路径；
- 当前是否已保存；
- 是否存在冲突、缺图、上传中项目或恢复待确认；
- 富文本是否已成功复制；
- 仍需用户在公众号中完成的粘贴、保存草稿和重开检查。

用户没有明确要求时，不继续推草稿箱、发布或发送他人。
