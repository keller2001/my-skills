# 吴颛个人写作总控

把本 Skill 作为个人写作规则的唯一入口。让个人声音优先于外部方法，让人工门禁优先于工具默认连续流程。

## 读取路由

1. 每次写作或审稿先读取 [个人写作风格](references/personal-style.md)。
2. 新文章、结构性重写或需要选择文章原型时，再读取 [写作方法库](references/writing-methods.md)。
3. 执行完整流程时读取 [个人写作工作流](references/controller-workflow.md)。
4. 写“驰昕AI共学营”时读取 [AI共学营账号配置](references/account-ai-colearning.md)。账号不明确且会改变写法时先询问。
5. 涉及真实 AI 应用故事、法律、医疗、金融、品牌争议、人物指控或隐私时，读取 [AI真实案例门槛](references/ai-article-gates.md) 和 [风险与授权边界](references/risk-and-authorization.md)。
6. 只有 WeWrite CLI 对任务记录、来源、检查、预览或发布确有帮助时，才读取 [WeWrite 适配器](references/wewrite-adapter.md)。不得依赖或寻找全局 `wewrite*` Skills。

## 选择流程

- 标题、错别字、局部润色和只审不改：采用最小流程，核对要求后做最小修改，不机械建立完整任务包。
- 新文章、个人故事、多来源文章和结构性重写：采用完整流程，先任务与证据，再大纲审查、人工批准、正文、独立审稿和人工定稿。
- 法律、医疗、金融、品牌争议、隐私、人物指控或现实影响内容：在完整流程上增加来源、措辞、隐私、合规、撤回和更正检查。

任务一旦改变核心观点、事实结构、公开风险或形成新文章，立即升级为完整流程。

## 人工硬门禁

### 门禁一：批准大纲

先形成任务卡、事实账本、主张与证据、缺口、文章大纲和配图计划；完整流程必须让独立审纲者检查真实材料，问题交回原规划者修复并由原审查者复审。最小流程不强制独立审纲。

AI 审纲通过后，向用户提交目标读者、文章问题、核心判断、标题方向、章节大纲、证据、缺失材料、风险、预计字数和图片计划，然后停止。用户明确回复“大纲通过”“按这个大纲写”或同等授权前，不得生成正文、配图、预览或发布。

### 门禁二：确认定稿

用户批准大纲后，才让同一主笔写正文。正文完成后，让独立审稿者检查真实全文、来源和实际图片；问题交回原主笔，原审稿者复审。

AI 审稿通过后，只能交付“AI 审过的候选稿”，并报告未核实内容、风险、字数和配图清单，然后停止。用户明确回复“定稿”或同等确认前，不得封存最终文章、把指定审核稿标记为定稿版、推入公众号草稿箱或发布。

### 门禁三：对外动作

把飞书审核稿、用户定稿、本地预览、公众号草稿箱和正式发布分别记录。同步指定审核文档不等于定稿或发布；推草稿箱、正式发布、对外发送、删除或覆盖原始资料分别取得明确授权。

## 任务包

完整流程可运行：

```powershell
python scripts/create-article-task.py <任务目录>
```

脚本只复制 [文章任务包模板](assets/article-task-package/)，不覆盖同名文件。填写后按阶段检查：

```powershell
python scripts/validate-article-package.py <任务目录> --stage planning
python scripts/validate-article-package.py <任务目录> --stage candidate
python scripts/validate-article-package.py <任务目录> --stage final
```

校验只发现缺失文件、待填写标记和状态冲突；不得把脚本结果当作事实核验、审纲通过、审稿通过、用户定稿或发布授权。

## 写作与审查

- 先区分个人经历、外部事实、AI 输出、作者判断和第三方观点，再写正文。
- 让同一主笔负责获批大纲后的正文和返修；不让审纲者代写方案，不让审稿者直接替主笔改稿。
- 按硬伤、风格、内容、活人感四层质检；不以机械口语、统一标点、固定篇幅或固定收尾代替个人风格。
- 简单任务可由当前 Agent 直接处理；只有独立审查收益明显时才增加角色。
- 同一关键问题返修两轮仍未解决时，缩小承诺或停止并请用户决定，不得假装通过。

## 工具边界

- 本 Skill 必须能独立建立任务书、事实账本、大纲、候选稿和审稿报告。
- WeWrite 只作为可替换执行后端，不得覆盖本 Skill 的个人风格和人工门禁。
- 用户要求对已有 `article.md` 做本机可视化排版或复制公众号富文本时，改用 `$prepare-wechat-rich-text`；不要在本 Skill 中启动编辑器。
- 配图、预览和发布都是正文之后的独立动作；未经对应授权不得自动连续执行。

## 状态与交付

严格区分：大纲待用户审核、大纲已批准、正文初稿、AI 审过的候选稿、用户确认定稿、带图稿、预览、草稿箱、已发布。

只向用户报告当前状态、文章解决的问题、目标读者、已核实事实、未核实内容、主要风险、字数、图片数、审核链接、预览路径和需要用户决定的事项。
