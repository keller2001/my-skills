# 任务模型分级

在执行大量检索、读取、写作、编码或调用工具前，先给出一次简短的模型建议。

## 边界

- 只做分级和建议，不声称已经切换当前任务的模型。
- 当前任务已经由某个模型启动；建议主要用于新任务、后续任务或获准的子任务。
- 区分“降低模型单价”和“减少 token 数量”，不要承诺切换模型必然减少 token。
- 分级不扩大用户授权，不自动创建子任务、修改配置、安装 Skill 或执行外部操作。
- 不为普通分级联网查价。只有用户要求最新价格或当前模型可用性时才查官方资料。

## 分级流程

按以下顺序判断：

1. 提炼任务目标和可核对的完成标准。
2. 检查五项因素：需求是否明确、推理是否复杂、后果是否高风险、过程是否容易验证、较低模型是否已经失败。
3. 应用高风险优先规则，再选择能够可靠完成任务的最低档模型。
4. 同时推荐推理等级；不要默认使用最高等级。
5. 用固定格式输出建议，然后再决定是否继续实质工作。

## 模型规则

### Luna：简单、确定、低风险

仅在以下条件同时成立时推荐：

- 指令明确且步骤固定；
- 输出容易立即核对；
- 错误后果较低且可逆；
- 不需要复杂判断、长链推理或跨来源综合。

典型任务：格式转换、明确字段提取、文件列表、简单分类、机械性改名和批量整理。

### Terra：日常默认

满足常规专业质量即可，或任务虽有多步但边界清楚时推荐。

典型任务：常规资料研究、普通写作、文档分析、标准代码修改、多文件核对、一般数据处理和工具编排。

默认选择 Terra；不要仅因文件多、步骤多或需要工具就升级 Sol。

### Sol：复杂、高风险或已经失败

出现任一重要信号时推荐：

- 需求模糊、约束冲突或存在多种高影响方案；
- 涉及安全、隐私、删除、资金、法律、医疗或其他不可逆后果；
- 需要架构决策、疑难调试、对抗性审查或长链推理；
- 结论很难验证，错误代价明显高于模型差价；
- Terra 已真实尝试并因能力不足失败。

不要因为用户使用了“重要”“认真”等笼统词语就自动升级。

## 推理等级

- `low`：机械、明确、容易验证。
- `medium`：日常默认，适合大多数 Terra 任务。
- `high`：复杂逻辑、关键边界或高风险复核。
- `xhigh`、`max`：只有任务确实困难且额外推理能带来可测质量收益时推荐。

## 输出格式

只用以下五行完成路由；理由保持一句话：

```text
任务等级：简单 / 常规 / 复杂
推荐模型：Luna / Terra / Sol
推理等级：low / medium / high / xhigh / max
理由：……
下一步：继续执行 / 建议更换模型后执行
```

如果无法确认当前模型，只给建议，不假设已经匹配。若任务包含不同难度的独立部分，可分别建议，但不要为了分级主动拆分或创建子任务。
