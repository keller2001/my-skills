# 任务模型分级

只在真正的新任务开始前正式分级一次。

## 先判断任务边界

- 同一任务中的继续、批准、补充、纠错、状态询问或完成剩余步骤：不重新分级，保持当前配置。
- “先读取、了解、接手”且后续目标已知：按完整后续目标分级，不按当前阅读动作分级。
- “先读取、了解、接手”但后续目标未知：保持当前配置完成接手；目标明确后再正式分级一次。

## 分级流程

1. 提炼任务目标和可核对的完成标准。
2. 检查五项因素：需求是否明确、推理是否复杂、后果是否高风险、过程是否容易验证、较低模型是否已经失败。
3. 选择能够可靠完成任务的最低档模型和必要的推理等级。
4. 核对任务是否已经开始，再决定继续、暂停或交接。

## 模型规则

- `Luna`：指令明确、机械、低风险、容易立即核对。
- `Terra`：日常默认；常规研究、写作、文档分析、标准代码修改、数据处理和工具编排。
- `Sol`：需求或约束复杂、高风险、难验证、需要架构或疑难推理，或 Terra 已因能力不足真实失败。

不要仅因文件多、步骤多、使用工具，或用户说“重要”“认真”就升级。

## 推理等级

- `low`：机械、明确、容易验证。
- `medium`：日常默认，适合大多数 Terra 任务。
- `high`：复杂逻辑、关键边界或高风险复核。
- `xhigh`、`max`：只有任务确实困难且额外推理能带来可测质量收益时推荐。

## 何时换模型

- 尚未开始实质工作：当前模型或推理等级与建议不匹配时暂停，等待用户调整；用户明确要求按当前配置继续时除外。
- 任务已经开始：不要仅为节约成本或档位不同而在原任务中切换。当前配置足够时继续完成。
- 只有任务范围或风险明显上升、当前模型确实能力不足，或当前模型不可用时，才建议更换；先生成简短交接，再用推荐配置新建任务。
- 工具、网络、权限、API 或参数错误不属于模型能力失败，先诊断错误，不据此升级模型。
- 无法确认当前配置时，只有尚未开始的新任务需要暂停确认；已开始的任务保持当前配置。

## 输出格式

正式分级只用五行，理由保持一句话：

```text
任务等级：简单 / 常规 / 复杂
推荐模型：Luna / Terra / Sol
推理等级：low / medium / high / xhigh / max
理由：……
下一步：继续执行 / 暂停执行，等待用户切换到 <推荐配置> / 生成交接，建议用 <推荐配置> 新建任务
```

后续目标未知的接手阶段不做正式分级，只说明：`保持当前配置完成接手；目标明确后再正式分级。`

只提供建议，不声称已经切换模型，不扩大授权，不自动创建任务或修改配置。普通分级不联网查价。

## 子智能体路由

- 创建每个子智能体前只分级一次，不直接继承主任务配置；显式传入推荐模型和推理等级。
- 子任务继续执行时不重复分级。接口不支持推荐模型时，改用当前可用且足够可靠的最低档模型并说明限制。
- 主智能体负责核对子智能体产出；分级不构成创建子智能体的授权。
